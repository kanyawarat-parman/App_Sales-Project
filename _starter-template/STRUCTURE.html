Starter Kit Anatomy

แผนผังโฟลเดอร์ _starter-template — สกัดจาก Taiyo Sales Project ไว้เป็นจุดเริ่มต้นของโปรเจกต์ถัดไปที่อยากได้แบบแผนเดียวกัน: Vue 3 Options API, ไม่มี build step, PHP vanilla + MySQL — จัดเป็น workspace 2 ชั้น (workspace รวม + แอปย่อยข้างใน) จำลองจากโปรเจกต์ต้นทางที่มี app-salesproject/ คู่กับ egp-import/

📁 D:\TAIYO\Project\Project_Claude\webfront_saleproject\_starter-template\

หลักการแบ่งชั้น

ชั้น 1 — ทั่วไป

ใช้ได้ทุกโปรเจกต์

โครงสร้าง auth, API pattern, format helper — ไม่ผูกกับธุรกิจไหนเป็นการเฉพาะ copy ไปวางแล้วรันได้ทันที

ชั้น 2 — เฉพาะโปรเจกต์

เขียนใหม่ทุกครั้ง

เมนู, enum สถานะ, badge สี, กฎ SLA — คำศัพท์และตรรกะที่ผูกกับธุรกิจของโปรเจกต์ใหม่นั้นๆ

โครงสร้าง workspace

workspace root

รวมทุก service ไว้ด้วยกัน

README.md/CLAUDE.md ระดับบนสุด — ไม่ใช่ตัวแอป แค่ชี้ทางไปแอปย่อยข้างใน เผื่ออนาคตอยากเพิ่ม service คู่กันแบบ egp-import ของต้นทาง

app-name/ · service-name/

แอปย่อยแยกอิสระต่อกัน

แต่ละโฟลเดอร์มี config//includes//.htaccess ของตัวเอง — ไม่มี code dependency ข้ามกัน เชื่อมกันได้แค่ผ่าน DB เดียวกันถ้าตั้งใจแชร์ข้อมูล

SharedMethods เดิม 29 ตัว — คัดแล้วเอามาแค่ไหน

9 ตัว — ทั่วไปจริง เอามาทั้งหมด
closeModal showAlert showConfirm avatarInitials formatPrice formatNumber formatNum formatDateTime formatFileSize

ไม่ผูกกับคำศัพท์ธุรกิจใดๆ — modal กลาง (AppModal), avatar, format ตัวเลข-วันที่

2 ตัว — ปรับ endpoint เป็น parameter ก่อนเอามา
loadSales → loadUsers(role) openDetail

pattern ทั่วไป แต่ของเดิม hardcode endpoint เฉพาะโปรเจกต์ (api/assignments.php ฯลฯ) ไว้ตรงๆ

18 ตัว — ไม่เอามา เขียนใหม่ทุกโปรเจกต์

statusBadge, priorityBadge, spStageStyle, docLabel, countdownColor ฯลฯ — hardcode string/enum ภาษาไทยเฉพาะของ e-Bidding/Sales Hunt โดยตรง
